# Phase 1.5 — Richer Demo Gallery (Timeline · Pacing · Cards · Real Content)

> Design spec. Status: approved in substance; pending written-spec review before planning.
> Builds on Phase 1 (client-side demo gallery). Author: Claude Code session, 2026-06-29.

## Goal

Make the demo gallery feel like a real product showcase instead of a list of bare
questions that flash by in seconds. Four cohesive pieces:

1. **Vertical research timeline** — a stepped, dotted progress rail (Plan → Research →
   Synthesize → Report) in the left column, with per-researcher rows nested under
   Research. Driven purely from existing stream state, so **live runs get it too**.
2. **Replay pacing** — replace the flat 800 ms gap clamp with a scaled schedule so a
   recorded run (real spans are 100–140 s) replays over a comfortable **~20 s** with a
   visible minimum dwell per stage and synthesis text that streams at a readable rate.
3. **Gallery cards (preview + metadata)** — enrich the manifest (derived from captured
   events, no re-recording) with a summary snippet + counts so cards show real
   substance, laid out as a hover-lift grid.
4. **Real content** — three real Sonnet runs (quantum supremacy, 2008 financial crisis,
   transformer models) replace the hand fixture.

## Non-goals / scope discipline

- **No backend pipeline changes.** The planner/researcher/synthesizer, SSE contract, and
  storage are untouched. Only `ara/demos.py` (pure builders) gains derivation logic.
- **No new runtime dependencies.** Timeline and cards are presentational; all derivations
  are pure helpers with vitest/pytest coverage, matching the existing pattern.
- **No live-stream protocol change.** The timeline reads the same `ResearchStreamState`
  the live UI already produces.
- Nothing from the v1 OUT list is added.

## Recorded content (already captured, committed as fixtures)

`frontend/public/demos/` holds three real, validated runs (no error events, full reports):

## Component 1 — Vertical research timeline (frontend)

### Pure helper: `frontend/lib/timeline.ts`

Derives the four stage nodes from stream state. No I/O, unit-tested.

```ts
export type StageKey = "plan" | "research" | "synthesize" | "report";
export type StageStatus = "pending" | "active" | "done" | "error";

export interface TimelineStage {
  key: StageKey;
  label: string;       // "Plan", "Research", "Synthesize", "Report"
  status: StageStatus;
  detail?: string;     // e.g. "3/5" for research
}

export function deriveStages(state: ResearchStreamState): TimelineStage[];
```

Derivation rules (from `state.status` + `state.agents`):

- **plan**: `idle` → pending; `planning` → active; otherwise done (a plan exists once we
  leave planning).
- **research**: pending before any agents exist; **done** the instant `researchComplete`
  (agents exist AND every agent is `done`/`error`) — this hand-off point is shared with
  synthesize below so exactly one stage is active in the pre-token gap; **active**
  otherwise (agents exist, not yet all finished); **error** only if *all* agents errored.
  `detail` = `${agents done-or-error}/${agents.length}`.
- **synthesize**: **active the instant research completes** (every agent `done`/`error`),
  not waiting for the first synthesis token — otherwise the rail shows nothing active
  during the synthesizer's pre-token thinking gap and looks stalled. Concretely: active
  once research is done OR `status === "synthesizing"`; done at `complete`. Pending only
  while research is still pending/active.
- **report**: pending until `complete`; done at `complete`.
- **terminal error** (`status === "error"`): the first non-done stage is marked `error`
  (a plan/synthesis-stage failure aborts the run; research-scoped errors do not — they
  surface on the individual agent row, consistent with the reducer).

### Component: `frontend/components/research-timeline.tsx`

Replaces `PlanTree` as the left-column panel. Renders, top to bottom:

- the existing plan header (question + "web search disabled" badge when applicable),
- a vertical rail of the four stage nodes: each a dot + connector line. Dot states:
  filled = done, pulsing = active, hollow = pending, destructive = error. Research shows
  its `k/N` detail.
- under the Research node, the per-researcher rows (question, last tool call, summary when
  done, per-agent status). The existing `AgentRow` markup from `plan-tree.tsx` is reused
  (extracted into a shared spot — `agent-status.tsx` already holds the status glyph;
  `AgentRow` moves into `research-timeline.tsx` or a small `agent-row.tsx`).

Visual language matches the current mono/uppercase/dot idiom (see `status-pill.tsx`,
`plan-tree.tsx`).

### Wiring: `frontend/components/research-live.tsx`

The `planPanel` switches from `<PlanTree .../>` to `<ResearchTimeline state={state} />`.
The mobile "Plan" tab shows the same component. `PlanTree` is retired (its header + agent
row logic move into the timeline). No other panel changes.

## Component 2 — Replay pacing (frontend)

### Pure helper: replace `computeDelays` with `computeReplaySchedule`

`frontend/lib/replay.ts` currently exposes `computeDelays(events: {t_ms}[], {maxGapMs})`.
Replace it with a schedule that also knows each event's `type` (to detect stage
transitions and synthesis tokens):

```ts
export interface ScheduledEvent { t_ms: number; type: string }

export interface ScheduleOptions {
  targetTotalMs?: number;   // default 20000 — whole replay ≈ this
  stageMinDwellMs?: number; // default 900  — min visible gap before a stage's first event
  synthMinStepMs?: number;  // default 14   — min gap between synthesis tokens (readable)
  maxGapMs?: number;        // default 1200 — clamp any single idle gap
}

// Returns the delay (ms) to wait before dispatching each event.
export function computeReplaySchedule(
  events: readonly ScheduledEvent[],
  opts?: ScheduleOptions,
): number[];
```

Algorithm (exact formulas pinned by TDD in the plan):

1. Raw gap `g_i = clamp(t_i − t_(i−1), 0, maxGapMs)`; `g_0 = 0`.
2. Scale factor `s = targetTotalMs / Σ g_i` (if `Σ g_i === 0`, fall back to even spacing
   across `targetTotalMs`). Apply `g_i *= s` — this normalizes both a 3 s toy file and a
   140 s real run to ≈ target.
3. **Stage dwell**: the first event of each new stage (`plan_ready`, first
   `researcher_started`, first `synthesis_token`, `report_complete`) gets
   `max(scaledGap, stageMinDwellMs)` so each stage is visibly distinct.
4. **Synthesis cadence**: each `synthesis_token` gets `max(scaledGap, synthMinStepMs)` so
   text streams steadily rather than in a burst.

Properties asserted by tests: empty → `[]`; total within tolerance of `targetTotalMs`
when raw spread is non-trivial; backwards/zero timestamps never produce negative delays;
synthesis tokens spaced ≥ `synthMinStepMs`; stage-first events ≥ `stageMinDwellMs`.

### Hook: `frontend/hooks/use-replay-from-json.ts`

Passes typed events (`{t_ms, type: e.event.type}`) to `computeReplaySchedule`, drops the
local `MAX_GAP_MS` constant (now an option default). The reset/timer/cleanup/`restart`
behavior is unchanged. Still drives the shared live `reducer`.

## Component 3 — Gallery cards + manifest enrichment

### Backend: `backend/src/ara/demos.py`

`build_manifest(payloads)` derives extra fields per entry **from each payload's
`events`** (so older recordings and the existing files need no re-recording):

- `summary`: `report_complete.report.executive_summary`, trimmed to ≤ ~160 chars on a word
  boundary with an ellipsis (falls back to `""` when no report event).
- `n_sources`: `len(report.citations)` (fallback: distinct source URLs across findings).
- `n_sub_queries`: `len(plan.sub_queries)` from `plan_ready` (fallback: count of
  `researcher_started`).
- `cost_usd`: last `cost_update.cumulative_usd` (fallback `0.0`).
- existing fields retained: `slug`, `title`, `question`, `model`, `created_at`, `n_events`.

Derivation logic goes in small pure functions (e.g. `_event_summary(events) -> dict`)
unit-tested in `backend/tests/test_demos.py` with a synthetic payload (not the big files).
`build_demo_payload` is unchanged (the recorder still rebuilds the manifest via
`build_manifest`).

### Frontend: `frontend/lib/demos.ts`

`DemoManifestEntry` gains optional, back-compatible fields:
`summary?: string; n_sources?: number; n_sub_queries?: number; cost_usd?: number`.

### Frontend: `frontend/components/demo-card.tsx` (new, presentational)

A single card used by both the gallery page and the homepage snapshot:

- question as the title (`title`/`question`),
- 2-line `summary` snippet (`line-clamp-2`) when present,
- meta footer: `{model} · {n_sources} sources · {n_sub_queries} sub-queries · ~${cost}`
  (each segment rendered only when its field is present),
- a "Watch replay ▶" affordance; the whole card links to `/demo/${slug}`.

`app/gallery/page.tsx` and `components/gallery-snapshot.tsx` render `<DemoCard>` in a
responsive grid (snapshot shows the first 3). The static `demoManifest` import and the
`/demo/[slug]` links are unchanged.

## Component 4 — Fixtures & tests

- The three real JSON files + rebuilt `manifest.json` are committed (key-free render in
  CI). The old `sample-quantum.json` is removed.
- `backend/tests/test_demos.py`: add cases for the enriched `build_manifest` (summary
  truncation, counts, cost, and the no-report fallback) using a small synthetic payload.
- `frontend/lib/timeline.test.ts`: cover `deriveStages` across idle/planning/researching
  (partial + full)/synthesizing/complete/error.
- `frontend/lib/replay.test.ts`: rewrite for `computeReplaySchedule` (the properties
  above).
- Optional insurance test (from the Phase 1 review): feed one real demo file through the
  shared `reducer` and assert it ends `status === "complete"` with a report — locks the
  recorder↔frontend contract.

## Data flow (unchanged spine)

```
record_run.py → _RecordingStore (full capture) → build_demo_payload → <slug>.json
                                                → build_manifest(all *.json) → manifest.json
                                                          │ (derives summary/counts/cost)
gallery/snapshot ── demoManifest (static import) → DemoCard → /demo/[slug]
/demo/[slug] → loadDemoEvents → useReplayFromJson(computeReplaySchedule) → shared reducer
            → ResearchLive(state) → ResearchTimeline(deriveStages) + ReportStream + Sources
```

## Risks & mitigations

- **Timeline drift from reducer semantics** — `deriveStages` is pure and unit-tested
  against the documented status/agent transitions; it reads the same state the reducer
  produces.
- **Pacing total drifts from target on pathological inputs** — tests assert tolerance and
  the helper falls back to even spacing when raw spread is ~0.
- **Large committed JSON** — intentional; they are the real demo content and the key-free
  CI fixtures.
- **Manifest back-compat** — new card fields are optional; a manifest entry missing them
  still renders (segments are conditional).
